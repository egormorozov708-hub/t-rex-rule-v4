## Быстро о главном

- `rule_v4` — одно небольшое изменение к `rule_v3`: `DROP` при низком птеродактиле, если прыжок уже начат. Физика игры не тронута.
- Ночной прогон: 131 игра × 10 млн кадров = **1 310 000 000 кадров, 0 смертей**; канонична JS-логика.
- Каждая игра воспроизводима по seed; все прогоны последовательные.
- «Бесконечно» не доказано — измерен только верхний предел частоты смерти ≈2,2·10⁻⁹ на кадр.

## Как это работает

Цикл за один кадр: **наблюдение → правило → действие**.

1. **Наблюдение:** из страницы берутся `type`, `oy`, `dist`, `type2`, `dist2`, `speed`, `jumping`, `ducking`, `oid`, `jumped_removed`.
2. **Правило:** порог `max(25, 17 · speed)`; отдельная ветка для птеродактилей и `DROP`, если прыжок уже начат.
3. **Действие:** `0` — бежать, `1` — прыжок, `2` — присед, `3` — `DROP` (ускоренное приземление).

| Препятствие | Условие | Действие |
| --- | --- | --- |
| Кактус / общий случай | `dist ≤ max(25, 17 · speed)`, не в прыжке | прыжок |
| Птеродактиль высокий (`oy 60–90`) | `dist ≤ 260` | присед |
| Птеродактиль низкий (`oy ≥ 95`) | `dist ≤ порог + 25` | прыжок |
| Любой, в прыжке | прыжок начат, его препятствие пройдено, впереди `CACTUS_LARGE ≤ 800` | `DROP` |
| Птеродактиль низкий (`oy ≥ 95`), в прыжке | препятствие прыжка пройдено | `DROP` |
| Иначе | — | бежать |

Быстрый режим отключает `requestAnimationFrame` и подменяет время виртуальными часами `dt = 1000/60`; вся игра считается внутри страницы одним `page.evaluate` на игру. Это даёт воспроизводимость по seed и ≈58–61 000 кадр/с. Канонична JS-логика `RULE_V4_JS` в [`rule_v4.py`](rule_v4.py); Python-зеркало служит только для parity: **7 seed × 200 000 кадров, MATCH 7/7** по действиям, кадрам и `distanceRan`.

## Быстрый старт

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python parity_v4.py --js-only --cap 3000 --seeds 792000   # 22 495.5 CAP
python watch.py --agent rule_v4 --cap 50000 --games 1 --seed0 792000 --headless
python parity_v4.py --cap 200000                           # MATCH 7/7
```

Требуется системный Google Chrome: оба режима используют `channel="chrome"`, fallback на bundled Chromium нет.

Игра загружается с `https://wayou.github.io/t-rex-runner/`; локальные исходники в репозиторий не входят. См. [`INSTALL.md`](INSTALL.md).

## Известные замечания

- ruff: осталось 4 предупреждения только в `rule_v2.py:19,89`, `rule_v3.py:15`, `rule_v4.py:11` (порядок импортов, SIM114) — файлы правила не трогались по условию проверки.
- Старые находки (`csv_watchdog.py:20,28`, `watch.py:426`, `watch.py:533`, отсутствие обработки сети/браузера) исправлены: `subprocess` с `check=False` и сообщением об ошибке, CSV через `with`, конкретные исключения, понятные подсказки по установке Chrome/Playwright и сети. `watch.py` завершается с кодом 2, остальные скрипты — с ненулевым кодом и подсказкой из `fast_env.py`. Поведение правила и физика не менялись.
- Исправлена перезапись служебных строк в CSV реального режима: `watch.py` больше не пишет `PROGRESS`/`fps` в CSV, а обновляет `mtime` своего файла через `os.utime` раз в ~30 с. `CSV STALE` в `watch.py` проверяет собственный heartbeat и работает только при `--csv`; от зависания игры защищают сторож прогресса (60 с без роста кадров) и внешний `csv_watchdog.py` (5 мин без изменения CSV).
- Верхняя граница частоты смерти (~2,2·10⁻⁹) оценочная: кадры не независимы, v4 подбирался по seed 786003 и 790015.
- Реальный режим проверен малой выборкой; один запуск потребовал перезапуска после таймаута.
- Настройки питания после ночного прогона восстановлены по остальным схемам, исходные значения не были захвачены.

## Ограничения

- «Бесконечно» не доказано — измерен только верхний предел частоты смерти.
- Оценка по правилу трёх предполагает независимые кадры; v4 подбиралось по смертям seed 786003 и 790015, поэтому цифра ориентировочная.
- Реальный режим проверен малой выборкой; один запуск потребовал перезапуска после таймаута.
- Python-зеркало проверено на 7 seed; при расхождении правят JS-эталон.

## Что не получилось

- RL-подходы (табличные v3–v6 и DQN) не воспроизвели это правило.
- Узкого места в Python-вызовах нет: в быстром режиме один `page.evaluate` на игру; оптимизация не дала выигрыша ≥10%.
- Тёмный режим удалён и не используется.
